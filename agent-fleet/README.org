#+TITLE: Agent Fleet

* Overview

This directory creates Hetzner Cloud servers and runs NixOS on them. OpenTofu
manages the cloud resources. The root NixOS flake installs and updates NixOS.

The file =nix/fleet.json= is the fleet inventory. OpenTofu creates every server in that file. The Nix flake creates a matching NixOS configuration for every server.

The initial fleet contains one =cx43= server, =agent-1=, in =nbg1=.

* Enter the development shell

Direnv loads =.env= and enters the Nix development shell:

#+BEGIN_SRC sh
cd /etc/nixos/agent-fleet
direnv allow
#+END_SRC

You can also enter it directly:

#+BEGIN_SRC sh
nix develop ..#agent-fleet
#+END_SRC

The main NixOS repository stores the fleet SSH key at
=../shared/secrets/agent-fleet-ssh.key=. Git-crypt encrypts it. The development
shell sets its local mode to =0600= after a checkout.

* Create a server

Run these commands from =/etc/nixos/agent-fleet=:

#+BEGIN_SRC sh
just tf-init
just tf-plan
just create agent-1
#+END_SRC

=just create= applies the OpenTofu plan and installs NixOS with =nixos-anywhere=.
It also adds the server to =~/.ssh/agent-fleet=. You can then connect from any
directory:

#+BEGIN_SRC sh
ssh agent-1
#+END_SRC

* Update a server

Edit the files in =nix/=, then run:

#+BEGIN_SRC sh
just check
just deploy agent-1
#+END_SRC

=just deploy= copies the flake, the Hyper Video Cachix netrc, and the R2
credentials to =/etc/nixos= on the server. It also copies the Syncthing password
hash. The recipe writes all three files as =root:root= with mode =0600=. It then
activates the configuration and refreshes the agent hooks. It also publishes
the Skillshare skills and installs or refreshes the ~lessismore~ plugin.

The first ~lessismore~ refresh bootstraps Codex, Claude, and Grok automatically. The refresh trusts a new Grok installation as part of this explicit update. Codex still requires manual hook trust through =/hooks= on each host.

NixOS keeps Tailscale running. Browser authorization during =just install= joins a new server to the tailnet once. Later deployments preserve that identity.

Update flake inputs before a deploy when you want new package versions:

#+BEGIN_SRC sh
just update-inputs
just deploy agent-1
#+END_SRC

* Add a server

1. Add one entry to =nix/fleet.json=.
2. Run =just tf-plan= and check the plan.
3. Run =just tf-apply=.
4. Run =just install SERVER_NAME=.
5. Run =just syncthing-id SERVER_NAME=.
6. Add the device ID to =/etc/nixos/shared/linux/syncthing.nix= and share the required folders with it.
7. Apply the local NixOS configuration with =just switch= in =/etc/nixos=.
8. Wait for the =configs= and =projects/ai= folders to finish syncing with =just sync-status SERVER_NAME=.
9. Run =just ensure-agent-hooks SERVER_NAME=.
10. Run =just sync-ai-resources SERVER_NAME=.
11. Run =just sync-auth SERVER_NAME= if the server needs your Codex and Claude sessions.

All servers use the shared NixOS configuration. Add a host-specific module only after a server needs different behavior.

=just tf-apply= regenerates =~/.ssh/agent-fleet= from the OpenTofu state. It also
adds =Include ~/.ssh/agent-fleet= at the top of =~/.ssh/config= once. Each entry
uses the public IPv4 address of the server and the SSH key in this repository.

* Remove a server

1. Remove the server from =nix/fleet.json=.
2. Run =just tf-plan= and check the plan.
3. Run =just tf-apply=.

OpenTofu removes the server. The apply command also removes its generated SSH
entry. Run =just ssh-config= to refresh the entries without changing any cloud
resources.

* Syncthing and dotfiles

Each server joins these existing Syncthing folders:

- =~/configs=
- =~/projects/ai=
- =~/projects/hyper=

Home Manager links the files used by Codex, Claude, Git, Herdr, Vale, Bash, Fish, GnuPG, AWS tools, and npm from =~/configs= into the expected paths.

Fish is the login shell for =robert=. Home Manager loads =~/configs/fish/config.fish= and its functions, completions, and history.

Check the remote copy status with:

#+BEGIN_SRC sh
just sync-status agent-1
#+END_SRC

The local NixOS Syncthing module uses =overrideDevices= and =overrideFolders=. Add each fleet device to that module. Changes made only in the Syncthing web UI do not persist.

** Web UI

Syncthing listens on =127.0.0.1:8384=. Tailscale Serve provides its HTTPS address to the tailnet:

#+BEGIN_SRC sh
just syncthing-ui agent-1
#+END_SRC

The current address is [[https://agent-1.taileff843.ts.net/][agent-1.taileff843.ts.net]]. Port =8384= remains closed in the NixOS and Hetzner public firewalls.

* OAuth credentials

OAuth tokens do not belong in the Nix store or a broad Syncthing folder. Copy the current Codex and Claude credentials over SSH:

#+BEGIN_SRC sh
just sync-auth agent-1
#+END_SRC

The recipe writes both files with mode =0600=.

* 1Password CLI

The fleet installs the headless 1Password CLI. Add your account once on each server:

#+BEGIN_SRC sh
just ssh agent-1
op account add --address my.1password.com
#+END_SRC

Enter your email address, Secret Key, and account password at the prompts. The account metadata remains on that server.

Run the Fish helper at the start of each session that needs 1Password:

#+BEGIN_SRC fish
1pass-login
op whoami
#+END_SRC

The helper calls =op signin --account my.1password.com=. The session expires after 30 minutes without activity. Run =op signout= to end it sooner.

* Common commands

Commands that take =HOST= accept one hostname or a comma-separated list. Omit
=HOST= to run the command on every host in =nix/fleet.json=.

| Command                        | Purpose                                      |
|--------------------------------+----------------------------------------------|
| =just tf-plan=                 | Show cloud changes                           |
| =just tf-apply=                | Apply cloud changes                          |
| =just ssh-config=              | Update =~/.ssh/agent-fleet=                  |
| =just install HOST=            | Replace the base image with NixOS            |
| =just deploy HOST=             | Copy and activate the Nix flake              |
| =just ensure-agent-hooks HOST= | Install the Herdr hooks and RTK Claude hook  |
| =just sync-ai-resources HOST=  | Refresh Skillshare and ~lessismore~          |
| =just ssh HOST=                | Open a user shell                            |
| =just sync-auth HOST=          | Copy Codex and Claude OAuth files            |
| =just syncthing-id HOST=       | Print the Syncthing device ID for a host     |
| =just sync-status HOST=        | Show Syncthing folder progress               |
| =just syncthing-ui HOST=       | Print the tailnet-only Syncthing UI address  |
| =just serve-cliproxyapi HOST=  | Open the CLI Proxy API control panel         |
| =just tailscale-login HOST=    | Authorize a new host in the browser          |
| =just tailscale-status HOST=   | Show the Tailscale connection state          |
| =just build HOST=              | Build the host configuration locally         |
| =just update-inputs=           | Update the flake lock file                   |
| =just tf-destroy=              | Destroy the Hetzner resources after approval |

* Installed agent tools

The system installs these tools from =llm-agents.nix=:

- Hermes Agent: =hermes=
- Antigravity CLI: =agy=
- Claude Code without the proxy: =claude=
- Grok Build through CLI Proxy API: =grok=
- Grok Build without the proxy: =grok-plain=
- Herdr: =herdr=
- CLI Proxy API: =cli-proxy-api=
- Claude usage: =ccusage=
- RTK: =rtk=

Codex comes from =codex-cli-nix=. Use =codex= through CLI Proxy API or
=codex-plain= without the proxy. Skillshare comes from =skillshare-nix= and is
available as =skillshare=.

CLI Proxy API runs as a user service and reads the synchronized configuration
from =~/configs/ai/cli-proxy-api/config.yaml=. Its OAuth credentials live in one
directory per host, =~/configs/ai/cli-proxy-api/auths/HOST=. Home Manager links
=~/.cli-proxy-api/auths= to the directory of the current host. The shared
=config.yaml= can name only one =auth-dir=, and CLI Proxy API does not expand
variables in it.

The control panel listens on the loopback address of its own host. Reach the
panel of a server from your workstation with =just serve-cliproxyapi HOST=, which
forwards the port over SSH and opens the page. =HOST= defaults to =agent-1=.

Log in on each server:

#+BEGIN_SRC sh
cli-proxy-api -config ~/.cli-proxy-api/config.yaml -claude-login
cli-proxy-api -config ~/.cli-proxy-api/config.yaml -codex-login
cli-proxy-api -config ~/.cli-proxy-api/config.yaml -xai-login
#+END_SRC

The per-host directories stop two hosts from overwriting the same credential
file, but they do not let two hosts share one account. Each provider rotates the
refresh token on every refresh and revokes the previous one, so give every host
its own login for every provider. When two hosts hold copies of one grant, the
host that refreshes last keeps working and the others fail with =invalid_grant=
and report =auth_unavailable=.
